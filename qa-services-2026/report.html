01

Итоговая сводка

Ответ для менеджера и владельца продукта.

Релиз не рекомендуется без исправления QA-001.

На мобильном Safari пользователь доходит до оплаты, но после подтверждения получает техническую ошибку; заказ остаётся в неопределённом статусе.

Главные риски

  • потеря оплачивающих пользователей;
  • дублирование заявки при медленной сети;
  • непонятная ошибка при просроченной сессии.

Ограничения

  • без нагрузочного тестирования;
  • без реальной банковской транзакции;
  • проверены Chrome и mobile Safari.

QA-001

После подтверждения оплаты отображается техническая ошибка

Critical
Окружение

iPhone, Safari, staging build

Предусловие

Пользователь авторизован; в корзине один товар.

Шаги
  1. Открыть корзину.
  2. Перейти к оплате.
  3. Выбрать тестовую карту.
  4. Подтвердить оплату.
Ожидание

Страница успешного заказа с номером.

Факт

«Unexpected error»; заказ в неопределённом статусе.

Доказательства

Видео, HAR, POST /api/payment/confirm → 500, request ID и console log.

QA-002

Двойной клик создаёт две одинаковые заявки

Major
Частота

4 из 5 повторов на Slow 3G.

Риск

Дубли в CRM и лишняя работа отдела продаж.

Результат

Кнопка не блокируется; отправляются два POST-запроса.
