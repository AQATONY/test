01

Итоговая сводка

Ответ для менеджера и владельца продукта.

Релиз не рекомендуется без исправления QA-001.

На мобильном Safari пользователь доходит до оплаты, но после подтверждения получает техническую ошибку и не видит понятного способа повторить операцию.

Главные риски

  • потеря оплачивающих пользователей;
  • дублирование заявки при медленном соединении;
  • непонятная ошибка при просроченной сессии.

Ограничения проверки

  • не проводилось нагрузочное тестирование;
  • не использовалась реальная банковская транзакция;
  • покрыты Chrome и Safari.

Пример подробного баг-репорта.

QA-001

После подтверждения оплаты в Safari отображается техническая ошибка

Critical
Окружение

iPhone 14, Safari, staging build

Предусловие

Пользователь авторизован, в корзине один товар.

Шаги
  1. Открыть корзину.
  2. Нажать «Перейти к оплате».
  3. Выбрать банковскую карту.
  4. Подтвердить тестовую оплату.
Ожидаемый результат

Страница успешного заказа с номером и дальнейшими действиями.

Фактический результат

Сообщение «Unexpected error», заказ остаётся в неопределённом статусе.

Доказательства

Видео, HAR, ответ POST /api/payment/confirm → 500, request ID и console log.

QA-002

Двойной клик по кнопке создаёт две одинаковые заявки

Major
Окружение

Windows, Chrome, Slow 3G.

Частота

4 из 5 повторов.

Результат

Кнопка не блокируется после первого нажатия; в CRM появляются две заявки с разными ID.

QA-004

На ширине 375 px сумма заказа выходит за границу карточки

Minor
Окружение

Chrome DevTools, 375 × 812.

Влияние

Не блокирует сценарий, ухудшает читаемость суммы.
