# Prompt для генерации чек-листа

```text
Ты Senior QA Engineer. Помоги составить первичный чек-лист для тестирования MVP формы создания заявки на перевозку для продукта "УЛ Лайт".

Контекст формы:
- Город отправления: автокомплит/выпадающий список из базы данных.
- Город назначения: автокомплит/выпадающий список из базы данных.
- Вес груза: числовое поле, кг, максимум 20 000 кг.
- Объем груза: числовое поле, м3, максимум 82 м3.
- Дата погрузки: датапикер, нельзя выбрать прошедшую дату.
- Кнопка "Рассчитать стоимость": отправляет POST-запрос к API, API возвращает цену в рублях или ошибку, если маршрут не найден.

Задача:
1. Сгенерируй чек-лист позитивных, негативных и граничных проверок.
2. Отдельно выдели проверки автокомплита, числовых полей, даты, кнопки и API-ответа.
3. Укажи ожидаемый результат для каждой проверки.
4. Не пиши автотесты, нужен именно тест-дизайн.
5. Не выдумывай поля, которых нет в описании.

Формат ответа:
Markdown-таблица с колонками:
ID | Область | Тип | Проверка | Ожидаемый результат
```

## Почему prompt составлен так

- Сначала задана роль и предметная область, чтобы модель не ушла в общую форму обратной связи.
- Поля перечислены точно по ТЗ, чтобы не появились лишние поля вроде телефона, ФИО или комментария.
- Явно запрошены позитивные, негативные и граничные сценарии.
- Указан запрет на автотесты, потому что задача просит test design.
- Формат задан таблицей, чтобы ответ было легче ревьюить и фильтровать.
