# Ревью сырого ответа ИИ

## Что полезно

- ИИ корректно разделил проверки по областям: города, вес, объем, дата, кнопка, API.
- Покрыты базовые positive/negative/boundary сценарии.
- Есть важная проверка двойного клика по кнопке.
- Есть проверка сброса результата после изменения входных данных.

## Что ИИ пропустил

| Область | Пропуск | Почему важно |
|---|---|---|
| Автокомплит | Не проверены stale/deleted значения из базы | Пользователь может выбрать город, который был удален или стал недоступен между выбором и расчетом |
| Автокомплит | Не проверены одинаковые города | Для перевозки это ключевое бизнес-правило: маршрут из города в тот же город может быть запрещен или требовать отдельной логики |
| Автокомплит | Нет проверки выбора только из списка | Если ручной ввод разрешен, API может получить город без ID и не найти маршрут |
| Числа | Не уточнены дробные значения | В логистике вес и объем часто дробные, но ТЗ не говорит о точности |
| Числа | Нет проверки `0`, `0.001`, разделителя `,` и пробелов | Эти значения часто ломают frontend/backend validation |
| Дата | Не проверена таймзона | "Прошедшая дата" зависит от часового пояса пользователя, сервера и склада |
| Дата | Нет проверки ручного ввода даты | Даже если есть датапикер, поле может принимать ввод с клавиатуры |
| API | Не указаны ожидаемые HTTP-коды | Для QA важно отделить `404 route_not_found`, `422 validation`, `500`, timeout |
| API | Нет проверки loading state | Без loading state пользователь может сделать повторный запрос |
| API | Нет проверки формата цены | Цена должна быть в рублях, с понятным округлением и без потери копеек/целых |
| Интеграция | Нет проверки соответствия client-side и server-side validation | Сервер обязан повторить валидацию, даже если frontend ее уже сделал |
| UX | Нет empty state для отсутствия подсказок | Пользователь должен понимать, что город не найден, а не видеть пустой список |

## Что в ответе слишком общее

- `AI-01` "все поля отображаются" полезно для smoke, но слабое как отдельная проверка без viewport/browser/context.
- `AI-08` объединяет два разных результата: подсказки найдены и подсказок нет. Лучше разделить.
- `AI-27` "API недоступен" слишком общий. Нужны timeout, `500`, network error, `429`, повтор после ошибки.
- `AI-29` не проверяет формат цены: валюта, разделители, округление, отсутствие отрицательной цены.

## Что удалить или перенести в низкий приоритет

| Проверка | Решение | Причина |
|---|---|---|
| AI-01 | Оставить как smoke | Слишком общая, но нужна для базового открытия формы |
| AI-08 | Разбить | Один символ и "ничего не найдено" являются разными сценариями |
| AI-29 | Переписать | Цена должна проверяться по формату и связи с request payload |
