# Блок 1. Тестирование требований: бизнес-процесс ЭТрН

## Состав блока

- `requirements_review.md` - анализ требований, риски вопросы.
- `business_process_checklist.md` - чек-лист основного процесса по BPMN.
- `xsd_form_checks.md` - проверки формы и XML-файлов по формату ФНС/XSD.
- `negative_cases.md` - негативные и edge-сценарии.
- `bug_reports.md` - 2 структурированных баг-репорта.

## Краткий вывод

Главный риск ЭТрН - рассинхронизация юридически значимого документа между участниками процесса. Ошибка в одном поле формы может стать не UI-дефектом, а проблемой приема XML в ГИС ЭПД, невозможностью подписать титул, неверным статусом перевозки или спором между грузоотправителем, перевозчиком и грузополучателем.

Поэтому тестирование разделено на уровни:

- бизнес-последовательность: кто, когда и какой титул подписывает;
- права и статусы: какие действия доступны роли в текущем состоянии;
- данные формы: обязательные поля, реквизиты, даты, масса, груз, порты, участники;
- XSD/XML: имя файла, кодировка, форматы дат, КНД, ИНН/КПП, обязательность элементов;
- интеграции: оператор ЭДО, ГИС ЭПД, QR-код водителя, электронная подпись;
- негативные сценарии: дубли сообщений, недоступность интеграций, ошибки подписи, замечания при погрузке/выгрузке.
